## YouTrack

Ссылка на проект: **ожидается от команды**. Создать задачи с ответственным, сроком, приоритетом, ожидаемым результатом и критериями приёмки. Использовать ID задачи в имени ветки и коммите/описании PR. Включать ссылку на PR/коммит обратно в задачу.

## Предлагаемые ближайшие задачи

| ID/задача | Результат и критерий завершения | Ответственный | Приоритет |
|---|---|---|---|
| Согласовать роли и YouTrack | Указаны роли всех участников, ссылка доступна команде | Команда | Must |
| Провести пользовательские интервью | 3–5 заполненных обезличенных записей, выводы связаны с требованиями | Назначить | Must |
| Проверить scope и правила назначений | Ответы на вопросы из requirements.md утверждены руководителем/клиентом | Команда | Must |
| Довести обзор литературы | 12 проверенных использованных источников, минимум 8 научных; таблица анализа заполнена | Назначить | Must |
| Завершить сравнение решений и технологий | 3–5 систем, единые критерии, 3 технических выбора с альтернативами | Назначить | Must |
| Проверить требования и диаграммы | Требования трассируются к сценариям, диаграммы отредактированы после обратной связи | Команда | Must |
| Подготовить визуальный прототип | Макеты ключевых сценариев и результат проверки с пользователями | Назначить | Should |
| Определить baseline и метрики | Согласованы процесс сравнения, условия и целевые пороги | Назначить | Must |

Заменить описательные названия на реальные YouTrack ID, ответственных и сроки после создания задач. Не фиксировать вымышленные статусы «выполнено».

## Ветки, ревью и релизы

- `main` — проверенная базовая ветка.
- Ветки: `<YT-ID>-<short-description>`.
- Для изменения открыть PR с задачей, кратким описанием и проверками.
- Командный PR должен быть проверен другим участником; для индивидуального проекта значимые изменения согласовывать с руководителем.
- Теги предзащиты создавать только на фактически проверенной версии; не перемещать ранее созданные теги.

## Риски

| Риск | Вероятность/влияние | Снижение |
|---|---|---|
| Нет доступа к пользователям/клиенту | Средняя/высокое | Попросить руководителя организовать контакт; явно описать ограничения evidence |
| Не подтверждены правила назначения и приоритетов | Высокое/высокое | Не закладывать спорные правила в код до интервью; записать решения |
| Чувствительные атрибуты студентов создают риск приватности | Средняя/высокое | Минимизировать сбор, ограничить доступ, обосновать необходимость и согласовать хранение |
| Командные роли/задачи не распределены | Высокая/среднее | Согласовать владельца и дедлайн для каждого deliverable в YouTrack |
| Заявленный real-time/production-ready превышает подтверждённое | Средняя/среднее | Использовать нейтральное описание проекта; проверять реальные нефункциональные свойства |
| Не успеть завершить обзор/диаграммы | Средняя/высокое | Приоритизировать источники и трассировку требований; не выдавать черновик за завершённый |

## Подготовка к предзащите

Показать структуру репозитория и историю; связать YouTrack-задачу с веткой/PR/документом; объяснить личный вклад каждого участника; показать замечания руководителя и исправления; продемонстрировать прототип или запуск приложения, если код готов; перечислить известные пробелы и следующие действия.
