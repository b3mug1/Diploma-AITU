# Сравнение технологий

Выбор предварительный; финальное решение должно быть связано с требованиями и доступными навыками команды.

## Backend-платформа

| Альтернатива | Сильные стороны | Компромиссы |
|---|---|---|
| FastAPI (выбрано предварительно) | Python, типизированные схемы, OpenAPI, async-возможности | Команда должна проверять границы транзакций и async-совместимость библиотек |
| Django + DRF | Зрелая экосистема, ORM и admin | Более тяжёлый framework; WebSocket требует дополнительного компонента |
| Node.js + NestJS | TypeScript во всём стеке, модульная структура | Потребуется отдельная экосистема и язык backend |

**Обоснование:** FastAPI соответствует описанному Python backend и позволяет документировать REST API через OpenAPI. Проверить навыки команды, тестируемость и требования к нагрузке.

## Хранилище данных

| Альтернатива | Сильные стороны | Компромиссы |
|---|---|---|
| PostgreSQL (предварительный выбор) | Реляционная целостность, транзакции, ограничения и индексы | Требует настройки/резервного копирования при реальном развертывании |
| MySQL | Зрелая реляционная БД | Возможности/поведение отдельных ограничений различаются; нужно проверить схему |
| SQLite | Простое локальное развёртывание и тестирование | Не является предпочтительным общим серверным хранилищем для многопользовательского развертывания |

**Обоснование:** студенты, шкафчики и назначения имеют явные связи и ограничения уникальности; реляционная БД упрощает обеспечение согласованности.

## Обновление интерфейса

| Альтернатива | Когда подходит | Компромиссы |
|---|---|---|
| WebSocket (предварительный выбор) | Двустороннее постоянное соединение и push-события | Управление reconnect, auth, доступностью и масштабированием соединений |
| Server-Sent Events | Односторонние события сервер→клиент | Не подходит, если клиенту нужен двусторонний канал |
| Polling | Прост в реализации и диагностике | Дополнительные запросы и задержка обновления |

**Обоснование:** если dashboard должен получать события от backend без обновления страницы, SSE также может подойти; WebSocket оправдан только при реальной необходимости двусторонней связи/интерактивных событий.

## Метод распределения

| Альтернатива | Преимущества | Риски/ограничения |
|---|---|---|
| Ручное решение администратора с цифровой очередью | Понятное ответственное лицо, легко объяснить | Не автоматизирует полностью и может быть непоследовательным |
| Детерминированные правила приоритета (рекомендуемый baseline для прототипа) | Прозрачно, воспроизводимо и тестируемо; не требует обучающей выборки | Требует согласования критериев, tie-breaker, апелляций и контроля ошибок входных данных |
| ML-модель для ранжирования | Может находить закономерности при наличии подходящих данных | Нужны качественные/законно используемые данные; непрозрачность, bias и сложная валидация; пока нет доказанной потребности |

**Предварительное решение:** для дипломного scope использовать объяснимый детерминированный алгоритм, если университет утвердит критерии. Называть его «ИИ» только при фактическом использовании и оценке ML; одного набора if/else недостаточно для такого утверждения. Рассмотреть human-in-the-loop: администратор проверяет результаты до публикации, а исключения фиксируются с причиной.
